Customer Management
POST /v1/customers Create Customer
Bearer {{sk_key}}
⚡
Next Move: Asynchronous Address Derivation
1. Capture response.id and save as customer_id in your environment.
2. The server creates the customer with wallets: "provisioning" and emits a Redis Streams event to cg_wallets.
3. WAIT 2–3 SECONDS, then call GET /v1/customers/{{customer_id}}/addresses to retrieve the generated crypto addresses.

Fiat Deposit Intents (NGN)
POST /v1/customers/:customer_id/fiat-deposit-intents Create Fiat Deposit Intent
Bearer {{sk_key}}
⚡
Next Move: Virtual Account Provisioning
1. Save response.id into fiat_deposit_intent_id.
2. Notice that va is initially null. The consumer cg.fiat contacts Lenco asynchronously to provision the dynamic virtual account.
3. Call Get Deposit Intent after 1–2 seconds to fetch the generated bank name, account number, and expiration timer.

Doc 5 §2.3, Doc 10 §2. Initiates an NGN bank transfer intent. `amount` is in minor units (kobo): 500000 = ₦5,000.00.

FieldTypeOptionsDescription

amount_mode string fixed | minimum | open Default is fixed. Enforces strict underpaid/overpaid intent checks.
⚠️ Provider Requirement: Real virtual account generation requires LENCO_API_TOKEN and LENCO_ACCOUNT_UUID in your local environment. Without them, the intent remains in pending status.

Crypto Withdrawals
POST /v1/crypto-withdrawals Initiate Crypto On-Chain Withdrawal
Bearer {{sk_key}}
⚡
Next Move: Store Withdrawal ID & Monitor Node Broadcast
1. Store response.id into crypto_withdrawal_id.
2. Fluxel validates destination format via crypto::is_valid_address.
3. The withdrawal executor confirms sufficient balance, constructs the raw transaction, and broadcasts to Alchemy/TronGrid.
4. Call Get Crypto Withdrawal to receive the confirmed txid and network_fee.

Doc 5 §2.4, Doc 1 §8.7. Transfers digital assets on-chain. Supported chains: bitcoin | ethereum | bsc | tron. Amounts are in minor units: wei for ETH/BSC, sat for BTC, sun for TRON.

🛡️ Internal Address Guard: If destination_address belongs to Fluxel, the API rejects it with 422 internal_transfer_unavailable to safeguard gas fees.

Webhooks & Event Deliveries
POST /v1/webhook-endpoints Register Webhook Endpoint
Bearer {{sk_key}}
⚡
Next Move: Save Secret Key & Configure Host Address
1. SAVE THE SECRET IMMEDIATELY: The secret is displayed once and cannot be retrieved again.
2. If testing locally on your host machine while Fluxel runs in Docker, use http://host.docker.internal:18080/ so the worker container can reach your host receiver (avoiding the container localhost trap).
3. Use the secret to verify the HMAC SHA-256 signature in incoming header X-Fluxel-Signature.
